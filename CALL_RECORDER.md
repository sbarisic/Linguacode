# Linguacode user guide

Build a Windows x64 folder containing the desktop app, matching audio host, and .NET runtime:

```powershell
./publish.ps1
./artifacts/linguacode-win-x64/Linguacode.exe
```

The app runs as the current user; administrator rights are not requested. Startup automatically checks the local audio installation and downloads/installs missing or outdated components using the existing managed setup. Existing installations and verified download caches are reused; an up-to-date installation does not reinstall. A visible banner shows setup progress, cancellation, and a Retry action if setup fails. Saved recordings remain usable and recording is available after a failed/cancelled setup; Transcribe and Resume transcription retry preparation automatically. If a shared capture is already active at launch, setup waits until transcription is requested after recording. Custom `--data-dir` is respected. Configure the summary provider under **Settings > Summary agent**.

The GUI accepts `--data-dir <directory>` and, for development, `--audio-host <matching-executable>`. Keep the published GUI and audio host together. Stop an older idle service explicitly before upgrading; the app does not replace incompatible running services.

## Recording a call

The desktop uses WPF Fluent controls, outline icons, and a native Windows title bar. Orange accents, peach selections, and light/dark palettes are defined in `src/Linguacode.Desktop/RecorderTheme.xaml`; change that file to experiment with colors. The app has no color settings. Windows high-contrast colors take precedence. The grouped toolbar provides recording, playback, transcription, Copy summary, and separate result/audio exports.

Top navigation offers **Home**, **Recordings**, and **Configuration**. Home shows a searchable recordings sidebar and three tabs: **Recording** for status and summary, **Transcript** for search/playback, speaker names and test Keep/Delete, and **Details** for coverage, exports and deletion. Recordings expands the library; double-click a call or press Enter to open it. Configuration contains the summary agent, audio devices, languages, ten-second test, and advanced processing limits. Use **Save changes** to apply the agent selection. Global settings remain drafts until Save changes. Starting or transcribing a recording does not apply unsaved configuration edits.

## Choosing a summary agent

Settings opens **Summary agent**. Choose ChatGPT, LM Studio, or Local. For ChatGPT, select a saved account or sign in through your browser, then refresh models and choose one. Sign-in can be cancelled. Accounts are stored in the selected data directory using Windows credential protection. For LM Studio or Local, enter the loopback server address and refresh models. Unloaded LM Studio models cannot be selected; load them in LM Studio first. A text-generation model is sufficient for summaries; tool-use support is not required.

Refresh models checks the connection without sending transcript evidence. You can enter a model ID and save while the server is offline. Saving validates the configuration format; generation checks actual model/account availability. Connection errors expose **Open agent settings**. Agent settings remain a draft until **Save changes**. Linguacode stores its selection under `<data directory>/desktop/preferences.json`. When explicitly using an existing AgentSmith data directory, saved model defaults are recognized without changing them.

Summary attempts retain their original agent identity. If you choose another agent, **Restart summary with selected agent** explicitly starts summary processing with that selection. Audio and transcription remain intact. A previous completed summary remains displayed/exportable until the replacement succeeds; its generating agent is shown separately from the current selection. Existing model-specific caches and uncertain-request retry checks still apply. Changing settings or restarting never silently retries an uncertain request.

## Recording controls

The window starts at 1060 by 740 logical pixels. Recording uses a fixed layout; long summaries scroll inside their own panel. With a saved recording selected, **New** opens a draft. Edit its title, choose output and microphone from the inline dropdowns, then click **Record**. These device choices apply only to that capture; global defaults remain unchanged.

New recordings default to `New call — yyyy-MM-dd HH:mm:ss` using local time. The timestamp refreshes when recording starts; custom titles are preserved.

Save default output and microphone devices in Configuration. A new recording starts with those defaults and can override either device in its draft. A headset is the supported baseline. Use the ten-second test to check both sides, then play it back in Transcript and choose Keep test or Delete test.

Device lists refresh automatically when Windows reports an added, removed, renamed, enabled/disabled, or default audio device change. Current selections are preserved; a missing selected device is restored automatically when the same endpoint reconnects. Updates wait until recording or processing finishes, so an active recording never switches endpoints. Refresh devices remains available as a manual fallback.

Use Windows defaults loads the current Windows communications output and microphone, falling back to multimedia defaults. Save changes remembers the selected device IDs across launches. If saved devices are disconnected at startup, the app waits and selects them when they become available. It does not substitute other devices or follow later changes to Windows defaults unless you choose Use Windows defaults again.

Home shows a compact output/microphone display beside the controls. While recording, it reflects the active capture's actual devices, including captures started by another client. Unavailable selections show the last known device name instead of a blank selector; reconnecting restores the selection without another click.

During recording, Stop saves both audio tracks and opens Transcript without starting transcription. During transcription or summary generation, Pause processing saves completed work for explicit resume. These controls appear only when relevant; capture itself does not pause. The Recording tab shows the summary directly. Transcript contains playback and speaker names; Details contains coverage, export/delete buttons and transcription controls. Summary citations open Transcript for timestamp playback.

Record and Stop control the shared audio service. Stop finalizes both tracks; transcription always requires an explicit click on Transcribe in the Transcript tab, including test recordings. The tab also offers distinct Resume and Retry actions when applicable. A changed default device never redirects an active recording. Device failures finalize the call as interrupted; analyzing retained parts requires explicit acknowledgment.

Call audio includes every application playing on the selected output. For VM calls, route playback through a host output and keep the microphone accessible to the host. USB devices passed exclusively into a guest are not made host-accessible by administrator elevation.

**Recorder microphone mute is independent of Teams/VM mute.** The recorder captures a separate microphone stream. Its mute replaces incoming microphone samples with silence before storage. Muting Teams alone may still leave your microphone audible in the recording. “You” means the microphone track, not verified speaker identity.

## Reviewing results

The transcript page includes a waveform timeline generated locally from retained audio, including recordings without a transcript. Orange audio precedes the playhead; the pale highlighted region identifies the selected transcript passage. Two thin passage lanes represent call output and microphone. Click a passage to select it and seek without changing the playing/paused state; simultaneous speakers on the same lane offer a standard selection menu. Hover for the speaker, source, timestamps and text. Waveform amplitudes are scaled for display only; playback volume is unchanged.

Click the waveform to seek, or drag anywhere on the waveform to preview a position and release to seek. Escape cancels a drag. Arrow keys seek by 0.1 seconds; Page Up/Down and the transport skip buttons move ten seconds. Zoom in/out changes the visible span by a factor of two down to five seconds; Fit shows the whole call. The horizontal scrollbar pans a zoomed view. Track changes retain zoom and position; a different recording starts fitted. Follow playback also keeps the waveform playhead visible. At short window heights the transcript and timeline scroll vertically rather than hiding transcript rows.

The track selector changes the waveform as well as playback; Both tracks shows peaks of the actual playback mix. Thin amber strips below the waveform indicate missing/uncertain audio; gray strips indicate intentional recorder mute. Selected passages use a soft background without an outline; keyboard focus is indicated around the playhead only. Tooltips distinguish these from inferred silence. Waveform loading runs in the background with cancellation and a local, versioned peak cache under `desktop/cache/waveforms`. Loading or cache errors leave seeking and the transcript available. The cache is disposable and does not change original audio, transcript evidence, service protocols, or model setup. The waveform provides playback navigation only: there are no trimming handles or transcript timing edits.

Search the transcript; double-click a timestamp or row background, or press Enter with the row focused, to play from its timestamp. Drag across passage or translation text to select it, then press Ctrl+C or right-click Copy. Double-clicking text selects a word. Right-click Copy passage copies the full passage; the toolbar Copy transcript action copies the entire recording transcript with timestamps and current speaker names. Text remains read-only. The playback button shows Play, Pause playback, or Replay: pausing preserves your position, and Replay at the end starts the recording from the beginning. The playback bar shows elapsed and total time, an orange seek track, play/pause, and ten-second backward/forward controls. Click the track to seek; dragging previews the time and seeks once on release. Cancelling a drag restores the current playback position. Times display milliseconds. Arrow keys move 0.1 seconds and Page Up/Page Down move ten seconds. The playback selector offers both tracks, call only, or microphone only. Transcript range markers sit below the seek track (call above, microphone below); click one to select its passage and seek. Playback highlights all active passages, including overlaps, and leaves gaps unhighlighted. Follow playback scrolls the list when the active passage changes. Hover a timestamp to see its exact time range and track. Right-click **Translate to…** to choose a target language; confirming sends only that passage to the saved summary agent. The chosen target does not change the summary language. Results are cached separately by passage, language and agent; the original transcript stays intact. Translation can be cancelled through Pause processing. The target language is shown by name. Translation uses transcript text, not audio: unclear recognition or unsupported speech may be untranslatable. The model must distinguish translated text from already-target-language and unable-to-translate outcomes. Unchanged responses are rejected; mostly unchanged responses carry a warning and are not cached, so an explicit click can retry. Translation cache versioning bypasses older unvalidated results.

Right-click a transcript passage and choose **Rename speaker…**, or select a row and press **F2**. The dialog updates that speaker throughout the recording without modifying recognition evidence. Transcript text editing and automatic echo cancellation are not included.

Generate summary is a separate action. It sends retained transcript evidence to the displayed configured provider; the audio stays local. Summaries retain citations to source segments. Changing speaker names or summary language marks a previous summary outdated. Summary failure does not remove the transcript. English, Croatian, and Slovenian have dedicated language choices; additional Whisper language codes are accepted in advanced settings.

Export results creates a new directory with timestamped TXT/SRT, original structured evidence, speaker-name mapping, coverage, and any saved summary. Export audio separately to retain the native tracks and timing manifest. Track playlists play chunks sequentially within each track; they are not a synchronized mixed call.

## Closing and recovery

Closing your recording asks to stop and exit; transcription remains pending. Closing processing asks to pause and exit. No tray mode is used. An existing recording started by another client is shown, but merely closing the GUI does not stop it. A crashed GUI can leave service-owned recording active; reopen and use Stop.

The app starts the matching hidden audio service when needed and tracks the exact process it launched. Normal exit waits for that service and its helper to stop after recording/processing cleanup, provided no other client or work needs them. A service that was already running before the app needed it is left alone. The conditional shutdown never forces another client's recording or inference to stop. If shutdown fails, the window stays open with an error so closing can be retried.

Completed work is retained. Resume is explicit, and failed/uncertain retries have separate checkboxes. Uncertain retries may repeat a request whose response was lost. Storage limits never delete older calls automatically. Advanced controls retain the defaults of 10 GiB per recording/analysis store, a 1 GiB free-disk reserve, and 30 minutes/100 summary requests per processing attempt. Increase limits or resume when necessary.

Version 1 recordings and analyses remain readable. New paired recordings and analysis jobs use version 2. The named-pipe service protocol is version 4; GUI and audio host must use the matching build. Live transcription, speakerphone echo cancellation, per-application capture, transcript editing, and embedded chat are deferred.

## Acceptance boundaries

Capture diagnostics distinguish Windows-reported glitches from inconsistent device position counters. Shared-mode Bluetooth positions may advance at a different rate than delivered samples. Forward positions, no glitch flag, and packet timestamps agreeing within 20 ms allow continuous sample placement; periodic timestamp anchors retain drift correction. Backwards/stalled counters require agreement within one frame. Delivered packets are preserved instead of trimming them against jittery timestamps. Capture threads use Windows multimedia scheduling priority.

New recordings retain discontinuity and uncertain-position flags as zero-duration diagnostic events: Windows does not supply a lost-audio duration. Positive microphone `Missing` intervals describe timing-based silence padding, not independently verified Bluetooth packet loss. These uncertainties may still produce `CompletedWithGaps`; they do not establish audible loss. Existing recordings are not rewritten. Packet callbacks only copy/mute and enqueue audio; level metering runs on the writer worker. Timing diagnostics include callback count, maximum callback time, callbacks exceeding their packet's audio duration (a diagnostic threshold, not a proven endpoint overrun), and queue overflows. Up to 32 flagged/regressed observations retain adjacent device positions and packet sizes rather than filling the sample with hardware/client rate mismatches.

A normal Stop completes recording and leaves transcription pending even when nonfatal glitches were reported. Such recordings show Audio warnings; coverage is retained and analysis reports CompletedWithGaps. Device loss, invalid timestamps, storage failures, forced stops, and crashes still require interrupted-recording confirmation. Existing recordings retain their original state and coverage; previously discarded samples cannot be recovered by upgrading.

Automated fixtures cover capture, mute, paired failure recovery, storage, timing, analysis overlap/reuse, summaries, and compatibility. Published-package checks use disposable data and synthetic audio. They do not establish headset/Teams/VM compatibility on every machine, transcription quality, or a successful real two-hour call.

Before treating those scenarios as accepted, run a two-hour Teams call and a VM call with a headset, verify both tracks at beginning/middle/end, test device unplugging and the two mute controls, and review English/Croatian/Slovenian speech against human transcripts. Record hardware, routing, recognition errors, and timing results. Mixed-language accuracy remains exploratory.

Transcription actions have separate buttons: Transcribe creates the first analysis, Resume transcription continues pending work, Retry failed steps retries only failed components, and Retry uncertain steps explicitly repeats only requests with unknown outcomes. Completed analysis with audio gaps alone offers no redundant transcription action. Summary actions likewise show Generate summary, Resume summary, or Update summary only when applicable. The Recording tab renders compact summary headings, bullets, emphasis, and timestamp citations; analysis IDs and export metadata remain in Details and exported files.

The selected summary model and Agent settings button sit at the top-right of the Call summary card. Hidden summary actions leave no empty action row. After generation, the card leads with the result in readable body text. A single summary point is displayed as a paragraph; longer summaries retain bullets and sections. Provider information, the accuracy note, and coverage warnings are grouped under the collapsed Summary details section. Provider disclosure remains expanded before the first summary request.

The Details tab has a recording-specific Source language selector (Auto detect plus all 99 languages supported by the pinned Whisper small model, sorted by language name; supported codes may also be typed). The choice applies when Transcribe is clicked. Auto-detected languages and language-score ranges are filled from saved evidence per audio track after processing; they describe audio chunks, not individual sentence accuracy. An explicit source language is labeled selected, never 100% detected. Resume locks the original source language; change Source language in Details, then use **Re-transcribe…** beside it to start over. After automatic detection the selector defaults to the detected language and its score (or score range), and remains editable. With mixed-language evidence, the most frequent chunk language is suggested; track-specific detection is available in the tooltip. Resume still uses its original language. Re-transcribe replaces only speech recognition results, summaries and translations; saved speaker evidence, speaker-name mappings and original audio are kept. The optional Use speaker names as spelling hints checkbox supplies renamed speakers as bounded Whisper hotwords. This can help spell names when spoken; it does not identify voices. Re-detect speakers is a separate Details action: it preserves recognition evidence and words while recomputing speaker assignments, clearing remote speaker names and derived summaries/translations; the microphone source name is retained. Both operations resume only their selected component after cancellation. Translation actions and provider disclosure are in the row/text context menu; transcript rows no longer contain a Translate button or permanent provider line.
